# 演示视频脚本（4~6 分钟）

> 录制前：`docker compose up -d`，执行 `backend/scripts/seed_demo.py --graph --ask`（真实模型约 $0.02）；浏览器窗口 1440×900；
> 准备两个浏览器窗口（或一个普通窗口 + 一个无痕窗口），分别登录 `kefu_zhang`（客服专员）和 `kefu_li`（客服主管）。
> 全程真实模型，约 $0.03。每段下面是“画面 → 解说要点”。第 5、7 段是阶段 7 补充的（可选，时间紧可以跳过）。

## 1. 开场（20 秒）
- 画面：登录页 → 用 `kefu_zhang` 登录。
- 解说：企业知识库与 Agent 平台；今天演示客服场景：有据可查的问答、深度调研、隔离与崩溃恢复。

## 2. 有据可查的问答（60 秒）
- 画面：新对话 → 右上角关联“客服知识库（部门共享）” → 问“买的衣服不合适，签收第 5 天了还能退吗？” → 回答逐字出现 → 悬停引用卡片看原文。
- 再问一个知识库里没有的：“你们支持比特币支付吗？” → Agent 说没找到，不编造。
- 解说：本地 embedding + 重排；预检索保证每个问题都先查知识库；引用是快照，文档以后更新也能看到当时的原文。

## 3. 部门隔离（30 秒）
- 画面：知识库页面，`kefu_zhang` 看到的客服知识库带“只读”标签、没有上传按钮；切到 `dev_wang`（研发部）登录，看不到这个知识库。
- 解说：服务层检查 + 数据库行级安全两道防线；漏写过滤条件时数据库也只返回该看的行。

## 4. 深度调研 + 崩溃恢复（90 秒，演示的重点）
- 画面：新建“深度调研” → 输入“整理客服知识库里关于退货、退款和发票的规则，写成一份新员工培训材料” → 出现计划卡片 → 写修改意见“只保留三个子任务” → 新计划 → 批准。
- 画面：子任务标签和工具时间线实时更新。**此时在终端执行 `docker compose kill -s SIGKILL worker && docker compose up -d worker`**。
- 画面：约 30 秒后继续执行（只重做没完成的子任务）→ 报告出现 → 点下载。
- 解说：等待审批不占 worker；计划和审批分在两个节点，恢复时不会重新生成计划；租约 + 心跳 + fencing 保证崩溃后被接管、不重复执行。

## 5. 数据分析：Agent 写代码、画图、交付文件（40 秒，可选）
- 画面：用 `dev_wang` 登录 → 新对话 → 问“帮我编一组 1 到 12 月的月销售额数据（单位万元），用 Python 画一张折线图，并把图片交给我。” → 工具时间线依次出现“加载技能 → 执行代码 → 准备下载文件” → 回答里直接显示折线图（中文正常），下面是 `chart.png`、数据表两张文件卡片 → 点下载。
- 解说：代码在断网、只读、非 root 的一次性容器里执行，只有 sandbox 服务持有 Docker socket；文件由 worker 复制成产物交付，api 不持有沙盒令牌。约 8 秒、4 次模型调用。

## 6. 知识图谱（30 秒）
- 画面：用 `kefu_li` 登录 → 知识库 → 知识图谱 → 搜索“退货” → 点节点看出处原文 → 选两个节点看最短关联。
- 解说：LLM 结构化抽取，按内容缓存，构建前给出费用预估；PostgreSQL 是事实来源，Neo4j 是可重建的派生存储。

## 7. 删除与安全（30 秒，可选）
- 画面：`kefu_li` → 知识库 → 新建一个“临时知识库”上传一篇文档 → 点文档行的“删除”（确认框说明会删掉什么）→ 再删除整个知识库。
- 画面（可选，登录页）：退出后用一个不存在的用户名（如 `demo-guess`）连续输错 6 次密码，第 6 次提示“尝试次数过多，请 15 分钟后再试”。不要用后面还要登录的账号演示：同一账号同一 IP 会被限制 15 分钟。
- 解说：删除时数据库里在一个事务内删掉事实数据，并写一条清理任务，向量库、原件、图数据库由后台清理——向量库停机时删除照样成功，恢复后自动补上；登录按“账号 + IP”限流，不会被人用错误密码锁住别人的账号。

## 8. 看板与收尾（30 秒）
- 画面：`kefu_li`（客服主管）→ 用量 → 切到“部门”→ 看每天的 token、请求与检索、按用户的费用；左下角切换深色模式。
- 解说：每次模型调用结束时由回调记录，崩溃前已花的钱也算得到；28 份决策记录、每个选型先做实验；CI 跑真实数据库的集成测试和依赖漏洞扫描。
