# 基础设施与能力深度取舍

企业级生产系统的基础设施按团队规模、运维分工和长期迭代节奏设计。AgentNexus 是 solo 开发、3-4 个月周期的简历项目，目标是**覆盖同样的能力广度**（RAG、知识图谱、多智能体、工具扩展、沙盒、多租户、Dashboard），但基础设施做了轻量化调整，避免把时间花在运维复杂度上而不是工程设计本身。

| 能力 | 生产级完整实现的常见做法 | AgentNexus 的选择 | 取舍理由 |
|---|---|---|---|
| 向量检索 | 分布式向量数据库 + 独立元数据协调服务 | 单节点 Qdrant 作为派生索引，PostgreSQL 为事实来源；本地 bge-small-zh + bge-reranker（decisions/0014、0016、0017） | 分布式向量库生产级但运维重；单节点 + 可从数据库重建（别名切换）已覆盖“索引可丢、可重建”的核心设计 |
| 文档解析/OCR | 自建多引擎解析与 OCR 服务集群 | pypdf / python-docx（decisions/0015），暂无 OCR | 自建模型服务成本高，用轻量库覆盖大部分文档类型即可；扫描件明确报“没有文字层”，可选接云端 OCR API |
| 任务队列 | 独立 worker 集群 + 专用消息队列 | 阶段 1-3 用 asyncio.Queue 单机版，阶段 4 升级到 ARQ + 独立 worker | 先把排队/持久化的语义想清楚，再引入真正的分布式执行，避免过早引入复杂度 |
| 工具沙盒 | 独立的沙盒 provisioner 微服务 | Docker SDK 在 worker 内直接起隔离容器 | 核心是"工具执行要隔离"这个设计理念，不需要复刻成独立微服务 |
| 多租户权限 | 用户/部门/资源级细粒度权限 + 操作审计日志 | 用户/部门两级、基本可见性隔离 | 保留"权限在后端强制执行"这一原则，不做到企业级的权限矩阵配置界面 |
| 扩展生态 | 支持在线安装第三方插件市场 | 配置文件形式的插件机制，本地/手动接入 | 在线安装是运营向功能，对简历项目价值不高 |
| 可观测性 | 全链路 trace 平台 | 可选接第三方 trace 服务，或自建简单的请求日志表 | 视时间富余程度决定是否接入第三方服务 |
| 知识图谱 | 向量库与图数据库双写互补、图谱参与检索 | Neo4j 作为派生存储（PostgreSQL 为事实来源，可重建），按知识库手动构建，先只做浏览与溯源（decisions/0019） | 选型时用基准对比过 PostgreSQL；保留 Cypher 与图算法的扩展空间；图谱参与检索要先有多跳评测集证明收益 |

## 原则

1. 每一项简化都要在 `docs/decisions/` 里留一条记录，写清楚"如果以后要按生产级标准扩展，应该怎么改"——这样面试时能证明这是主动取舍而不是能力不够。
2. 不简化的部分：Agent 请求落库 → 排队 → 派发执行 → 状态推流这条主链路的正确性（幂等、可恢复、可观测），这是整个项目最有技术含量的地方，值得投入最多时间。
