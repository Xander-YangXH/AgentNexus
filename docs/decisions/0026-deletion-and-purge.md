# 0026 - 阶段 7.1：删除知识库与文档（数据库事务 + 清理任务发件箱）

**状态**：已采纳（2026-10-25）。用户休息期间授权按推荐方案自主推进，本记录里的选择都是我按推荐方案定的，没有经过逐项确认；理由和备选写在下面，可以复核。

**背景**：项目一直没有删除知识库和文档的接口（`SECURITY.md` 的已知局限）。阶段 6.4 做端到端测试时，删一个测试知识库只能分别清理数据库、Qdrant 和原件目录三个地方。用户删不掉自己上传的数据，既是功能缺口，也是数据治理问题。

难点在于一篇文档的数据分布在四处：

| 存储 | 内容 | 角色 |
|---|---|---|
| PostgreSQL | 文档、分块、图谱的实体 / 关系 / 出处、抽取缓存、构建记录 | 事实来源 |
| Qdrant | 每个分块一个点 | 派生索引 |
| 原件目录 | 上传的原始文件 | 派生副本（处理时读） |
| Neo4j | 知识库的图 | 派生存储 |

## 一、实验（`backend/eval/deletion_exp/scale.py`，零费用，不留数据）
| 操作 | 规模 | 耗时 |
|---|---|---|
| PostgreSQL 删除知识库（级联分块、图谱出处） | 1000 篇 × 100 块 = 10 万个分块 + 10 万条出处 | 1.21 秒（事务内，随后回滚） |
| Qdrant 按文档过滤删除 | 20000 个点里删 100 个 | 6ms |
| Qdrant 按知识库过滤删除 | 19800 个点 | 0.06 秒 |

**结论**：删除本身不慢，同步做完全可以。真正的问题不是性能，而是**一次请求要改四个存储，任何一个暂时不可用时怎么办**。

## 二、选项
### 1. 跨存储删除怎么做
| | A. 请求里依次删四处 | B. 软删除（墓碑）+ 后台清理 | C. 数据库硬删除 + 清理任务发件箱（采用） |
|---|---|---|---|
| 做法 | 删 Qdrant → 删原件 → 删 Neo4j → 删数据库 | 文档 / 知识库加“删除中”状态，后台删完派生副本再删行 | 一个事务里删掉数据库的行，同时插入一条清理任务；worker 清理派生副本，失败退避重试，成功后删任务 |
| 某个派生存储不可用时 | 要么删除失败（用户删不掉），要么吞掉错误、留下残余 | 删除成功；清理稍后完成 | 删除成功；清理稍后完成 |
| 数据库里立即看不到 | 是 | **否**：每一个读路径（列表、检索、图谱、关联、权限检查）都要加“排除删除中”的条件，漏一处就泄露 | 是：行已经不在了 |
| 代价 | 失败处理复杂；没有重试 | 改动面大 | 多一张任务表；派生副本最多晚几秒删除 |

选 C 的理由：
- 删除是否成功只取决于数据库事务。提交即删除，而且"一定会被清理"也在同一事务里落库，不会出现"删了数据、清理任务丢了"或者反过来的情况；
- 派生副本晚几秒删除是安全的：检索时 Qdrant 的结果要回数据库取原文，没有对应分块的点会被过滤掉；
- 清理任务沿用阶段 4.1 的租约队列（认领、心跳、fencing、崩溃接管），只加了一个"最早执行时间"列用于退避。每一步都幂等，重做没有问题。

### 2. 删除文档后图谱怎么办
| | a. 自动重新构建图谱 | b. 只提示"图谱已过期" | c. 按剩余的出处裁剪（采用） |
|---|---|---|---|
| 被删文档的内容 | 重建后消失 | **仍然留在图里**，用户可能看不到提示 | 只出自这篇文档的实体和关系立即删除 |
| 费用 | 如果有还没抽取过的新文档，会**未经确认就花钱**（违背 0019 的"先预估、再确认"） | 无 | 无 |

c 的做法：分块被删时出处已经级联删除，然后在同一事务里：
- 删掉没有任何出处的关系和实体；
- 按剩余的出处重算提及次数；
- 删掉不再对应任何分块的抽取缓存（缓存里是从被删文本里抽出的内容，也是派生数据）。

清理任务随后按数据库重写 Neo4j。局限：同时出现在别的文档里的实体，它的描述可能还带着被删文档的信息。没有新文档时重新构建图谱全部命中缓存、不花钱，可以重算描述。

### 3. 其他规则
- **谁能删**：只有知识库所有者。部门共享的成员只读（403），看不见的 404。
- **图谱构建进行中不能删**（409 `graph_build_in_progress`）：构建会用删除前读到的分块写出处，并在结束时重写 Neo4j。删除事务先锁住知识库这一行；新建构建的插入要拿这一行的共享锁（外键检查），所以两者串行。
- **处理中的文档可以删**：入库的写回都带租约版本号，行没了就写不进去，worker 会丢弃自己写的点；心跳也会发现租约没了。认领之后、开始处理之前被删的，直接跳过。
- **对话里的引用快照保留**：那是用户当时看到的回答的一部分。同部门成员对话里对被删知识库的关联随外键级联删除（外键动作不受 RLS 限制）。

## 三、实现
- 迁移 `0012`：`purge_jobs` 表，包含类型、知识库、文档、原件 key 列表、租约字段、`not_before`、`last_error`。不加外键（被删的行已经不在）；不启用 RLS（api 只插入）。
- `services/purge.py`：
  - `prune_graph`：在删除事务里裁剪图谱；
  - `PurgeService`：删 Qdrant 的点（按文档或按知识库过滤）、删原件、重写或删除 Neo4j 里的图。失败按 5、10、20 秒……退避，最长 10 分钟，不设次数上限：删除必须最终完成。
- `KnowledgeService.delete_document` / `delete_kb`，接口 `DELETE /api/documents/{id}`、`DELETE /api/knowledge-bases/{id}`（204）。
- `LeaseQueue` 新增可选的 `not_before` 列：退避期内不认领。
- worker 新增 `purge` 派发器（一个执行槽），NOTIFY 通道新增 `purge`。
- 前端：文档行和知识库标题栏的删除按钮。确认框说明会一起删掉什么、什么保留；共享的知识库会额外提醒"同事对话里的关联也会移除"。

## 四、验证
- 测试：删除相关 10 个（文档 / 知识库各存储的清理、失败退避重试、幂等、处理中删除、认领后删除、图谱裁剪、只出自被删文档的关系、构建中拒绝、两种数据库角色下的权限与级联）；后端全量 310 个通过。
- 变异检查 13 项全部被测出。第一次有 1 项没测出："不删没有出处的关系"。测试数据里这类关系的端点实体也被删了，靠级联就消失了；补了"两端实体都还在、关系只出自被删文档"的测试后测出。
- compose 实测（经 Nginx、真实 worker）：
  - 删除文档：204，随即 404；清理约 0.1 秒内完成（NOTIFY 唤醒），点和原件都没了，另一篇不受影响；
  - 删除知识库：同上；
  - **停掉 Qdrant 再删除**：删除仍然 204（11ms），随即 404；清理任务失败两次、退避 10 秒；Qdrant 恢复后 7 秒内清理完成，剩余点数 0；
  - 浏览器里删除文档和知识库，确认框文案正确，列表随即更新。
