# 0027 - 阶段 7.2：Agent 把沙盒里的文件交给用户（share_file）

**状态**：已采纳（2026-10-25）。用户休息期间授权按推荐方案自主推进，选择由我按推荐方案决定，理由和备选写在下面，可以复核。

**背景**：数据分析技能能在沙盒里画图、算表，但文件只存在于对话的工作目录里，用户拿不到（4.2 的待办）。回答里只能写“图已保存为 chart.png”，用户看不到图。调研报告（0022）已经有一套“产物”机制：原件存储、`artifacts` 表、下载接口、消息上的附件卡片。

## 一、选项
| | A. 工具 `share_file`：模型显式交付，worker 复制成产物（采用） | B. api 开放“工作目录文件下载”接口 | C. 每次执行代码后自动把新文件都作为附件 |
|---|---|---|---|
| 权限 | 取文件、写产物都在 worker 里；api 不需要沙盒令牌 | api 要拿到沙盒令牌（能执行代码），违背 0021 的“每个服务只拿自己需要的权限” | 同 A |
| 交付什么 | 模型决定（技能说明里要求交付图表、整理好的表格） | 用户自己在文件列表里找 | 临时文件、中间结果也会被当成附件 |
| 复用 | 产物表、下载接口、附件卡片全部复用 | 新接口、新页面 | 同 A |

## 二、实现
- **sandbox 服务**：新增 `GET /workspaces/{id}/file/raw?path=`，原样返回字节，最大 5MB。路径校验与文本读取相同。
- **工具层**：工具除了返回文字，还可以返回 `ToolOutput(text, attachments)`。`share_file` 读取文件，用 `ArtifactService.save` 写入原件存储，返回附件描述。只有 worker 里提供了产物存储时才有这个工具。
- **图的状态**：`ChatState.attachments`（追加合并）。附件随 checkpoint 保存，worker 被接管后不会丢、也不会重复交付。最终成为回复的 `attachments`，由派发器在完成 run 的同一事务里写入 `artifacts` 表（0022 的路径）。
- **上限**：一次回答最多 5 个文件，超出的调用直接拒绝并告诉模型。
- **内容类型**：只给 PNG、JPEG、GIF、WebP、CSV、文本、Markdown、JSON、PDF、xlsx 保留原类型，其余一律 `application/octet-stream`。HTML、SVG 能执行脚本，不保留。下载接口本来就强制 `attachment` + `nosniff`。
- **前端**：附件按类型显示图标；PNG、JPEG、GIF、WebP 直接预览（只用 `<img>`），底色用 `--an-figure-bg` token（暗色模式下也是白底，图表按白底设计）。
- **技能说明**：画完立即 `share_file`；不要 `read_file` 图片；图里可以直接写中文。

## 三、实现中发现的问题
1. **【重点】新对话的第一步执行代码就写不了文件**（4.2 起就存在的潜在问题）：
   - 现象：真实模型的端到端测试里，模型画图时 `PermissionError`，于是到处找可写目录，把 8 轮工具调用都用完了。
   - 根因：compose 里工作空间是命名卷的子目录挂载。Docker 把**空**卷挂到镜像里已存在的目录（`WORKDIR /workspace`，root 755）上时，会把镜像目录的内容**连同属主和权限**复制到卷上（copy-up），sandbox 服务事先设好的 777 被改回 root 755，沙盒里的 nobody 写不进去。
   - 为什么之前没发现：本机测试用绑定挂载，没有 copy-up；4.2 的 compose 验证第一步是经服务写 CSV，工作空间已经不空。
   - 解法：挂载加 `no_copy=True`。对照实验：不加时容器内 755、写入被拒；加了 777、写入成功。补了回归测试（检查挂载参数）。
2. **模型把工具轮数浪费在中文字体和读图片上**：镜像里没有中文字体，图里的中文是方框，模型反复找字体、换字体；画完还用 `read_file` 读 PNG，一大段乱码进了上下文。
   - 修复：沙盒镜像装文泉驿微米黑（Debian 官方包，下载 1.6MB、安装后约 5MB），用 `MATPLOTLIBRC` 设为默认字体；`read_file` 遇到二进制文件直接拒绝，并提示用 `share_file`；技能说明写清楚。
   - 效果：同一个问题从 10 次模型调用、没交付文件，变成 4 次调用、8 秒，交付了图表和数据表。

## 四、验证
- 测试：sandbox 原样读取（二进制不变、路径与大小校验、跨工作空间读不到）、二进制文件不能按文本读、挂载参数；`share_file` 的内容类型与产物写入；回复带附件、一次最多 5 个；接管后附件从 checkpoint 恢复且不重复交付。后端全量 318 个通过；前端 69 个。
- 变异检查 7 项全部被测出：附件不进状态、回复不带附件、不限数量、保留所有类型、原样读取不限大小、原样读取不校验路径、去掉 `no_copy`。
- compose + 真实模型（DeepSeek，3 次，合计不到 $0.01）：
  - 第一次暴露了权限问题；
  - 第二次暴露了字体和读图片的问题；
  - 第三次 8 秒、4 次模型调用，交付 `chart.png` 和 `monthly_sales.csv`，下载类型正确、带 `attachment` 和 `nosniff`；
  - 浏览器里浅色 / 深色模式下图片预览正常，中文正常显示。
