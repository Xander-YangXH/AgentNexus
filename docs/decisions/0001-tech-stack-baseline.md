# 0001 - 技术栈基线与轻量化取舍

**状态**：已决定（阶段 0）

**背景**：设计一个 3-4 个月的 solo 简历项目，目标是覆盖企业级知识智能体平台的完整能力广度，需要在"覆盖能力广度"和"solo 可交付"之间取舍。

**决定**：见 [../tech-tradeoffs.md](../tech-tradeoffs.md) 的完整对照表。核心原则是保留每种能力的"设计理念"，简化其"生产级实现规模"。

**后果**：基础设施更轻，部署更快；但部分子系统（如多租户权限、扩展生态）不具备生产级系统的完整功能深度，需要在简历/面试中主动说明这是刻意的范围取舍。

**验证**：`docker compose up` 能在普通笔记本上跑起全部服务。
