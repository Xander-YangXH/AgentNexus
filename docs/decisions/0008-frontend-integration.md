# 0008 - 前端如何接入：同源代理、fetch 读取 SSE、Nginx 提供静态文件

**状态**：已决定（阶段 1.6，2026-10-21）

**背景**：前端技术栈在 0001 已定（Vue 3 + Vite + Ant Design Vue）。这一步要决定的是它怎么与后端连接：跨域怎么处理、流式事件怎么读、部署时谁来提供页面、模型输出怎么安全地渲染。

## 决定

1. **同源访问后端，不配 CORS**。前端代码只请求相对路径 `/api/...`：开发时由 Vite 开发服务器代理到 `localhost:8000`，部署时由 Nginx 转发到 compose 里的 `api:8000`。浏览器只看到一个源。
   - 否掉的方案：前后端不同源 + 后端开 CORS。多一份跨域配置要维护，且带凭据（阶段 5 的 token/cookie）的跨域请求规则更复杂，容易配错。
2. **用 fetch + 流式读取解析 SSE，自己写解析器**（`web/src/api/sse.ts`，约 150 行含注释，17 个单测中有 11 个针对它）。
   - 否掉原生 `EventSource`：不能带自定义请求头，而鉴权在头里（现在是 `X-User-Id`，阶段 5 是 token）。也不把用户标识放 URL 查询串（会进访问日志和浏览器历史）。
   - 否掉 `@microsoft/fetch-event-source`：最后一次发布是 2021 年（2.0.1）；我们需要的只是“解析 + 带 `Last-Event-ID` 重连 + 收到终态就停”，自己写可以完整测试每个边界（数据块任意切断、`\r\n` 跨块、多字节字符跨块、空块），也更容易讲清楚。
3. **重连策略**：网络错误或服务端在终态前关闭连接时重连，带 `Last-Event-ID`；401/404 等客户端错误不重试；连续失败超过 5 次放弃；收到数据即重置失败计数。合成的终态事件没有 id，不会覆盖续传游标。
4. **以数据库为准刷新界面**：发送成功后、收到 `run.completed` 后都重新拉取消息列表，而不是在前端拼接；临时回复只在生成过程中显示。失败时保留半截文本并标成“生成中断”（0007 已确认不入库）。
5. **刷新页面能接上正在生成的回复**：新增 `GET /api/conversations/{id}/active-run`；页面加载对话时若有活跃 run 就重新订阅，事件流从头回放，已生成的部分立刻补齐。“等待首字”的计时从服务端的 run 创建时间算起。
6. **渲染安全**：模型输出用 markdown-it 渲染且 `html: false`，原始 HTML 一律当文本显示（防 XSS），`javascript:` 链接不会被生成。
7. **部署形态**：多阶段镜像——Node 22 构建（`npm ci --ignore-scripts`，类型检查 + 打包），Nginx 1.28（稳定分支）只提供静态文件并转发 `/api`。Nginx 对 `/api` 关闭缓冲（`proxy_buffering off`）作为兜底：后端 SSE 响应已带 `X-Accel-Buffering: no`，实测仅靠这个头也能逐段到达；全局关闭是为了以后新增的流式接口忘了带头时也不被缓冲。
8. **依赖版本**：全部固定到确切版本并提交锁文件；只选发布满两周的版本（刚发布的版本若有问题或被投毒，通常在头一两周内被发现）；TypeScript 用 6.x 而非 7.0（7 是大版本重写，`vue-tsc` 依赖它的 JS 接口，兼容性未知）。

## 后果

- 好处：没有跨域配置；流式客户端的每个边界都有测试；刷新不丢正在生成的回复；部署镜像里没有 Node 和 node_modules（93.7MB）。
- 代价：自写解析器需要自己维护；`GET /api/users` 会列出所有用户，只能作为鉴权占位期的开发便利（阶段 5 删除）。
- 已知局限：失败的回复刷新后看不到失败原因（失败信息在 `agent_runs.error`，界面只在当次会话里显示）；错误信息直接显示了供应商的原始报错，面向真实用户前需要改成友好提示并避免泄露内部信息；还没有“停止生成”（依赖取消 run 接口）。

## 验证

- 前端单测 17 个（解析器 5 个场景组、重连 6 个、状态机 3 个、Markdown 安全 3 个），变异检查 5 项均被抓住。
- 后端新增 2 个接口测试（共 61 个）。
- 浏览器实测（开发模式与 Nginx 打包版本）：创建用户 → 新对话 → 发消息 → 逐段显示；`<script>` 显示为文本、DOM 中无 script 元素；生成中刷新页面，0.6 秒内补齐已生成部分并继续增长；Gemini 返回 503 时显示“生成中断”及原因。
- 经过 Nginx 的 SSE：22 个事件分散在 3.08 秒，最大推送延迟 23 毫秒；去掉 `proxy_buffering off` 后仍逐段到达（验证了“响应头即可关闭缓冲”）。
