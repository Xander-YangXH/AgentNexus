# 0010 - LangGraph checkpoint 的保留与清理

**状态**：已决定（阶段 1 收尾，2026-10-21）

**背景**：决策 0006 让每次执行都把整段对话历史喂给图，checkpoint 按 run 划分。0006 当时写了“清理与存储增长未测量”。这一步先测量，再决定怎么清理。

## 测量（真实聊天图 + 真实 PostgreSQL，每轮用户消息约 1KB）

| 消息内容 | 第 1 轮单个 run | 第 10 轮 | 第 20 轮 | 20 轮累计 | 对话文字本身 |
|---|---|---|---|---|---|
| 重复文字（`"测" * 340`） | 8 KB | 8 KB | 11 KB | 174 KB | 41 KB |
| 随机中文（几乎不可压缩） | 9 KB | 36 KB | 66 KB | **756 KB** | 41 KB |

- 每个 run 的 checkpoint 存了整段历史（而且一个 run 有多个 checkpoint 版本），所以**单个 run 的大小随轮数线性增长，一个对话的总量随轮数平方增长**。随机内容下，20 轮累计是对话文字本身的 18 倍；按斜率推算，100 轮的对话约 16 MB。
- 第一组用重复文字测，数据库的 TOAST 压缩几乎把它压没了，严重低估问题。**测量数据必须接近真实数据的可压缩性**。

## 决定

1. **run 结束后保留 24 小时再清理**（`CHECKPOINT_RETENTION_HOURS`），每 10 分钟检查一次（`CHECKPOINT_JANITOR_INTERVAL_SECONDS`）。checkpoint 只对“进行中”的 run 有用（中断恢复、崩溃接管，见 0006），结束后保留一段时间供排查即可。
2. **用自己的列记账**：`agent_runs.checkpoint_purged_at`（迁移 0004），而不是直接查询 LangGraph 管理的 `checkpoints` 表。LangGraph 的表结构由它自己演进，我们不依赖它的内部结构；删除用它提供的 `adelete_thread`（幂等，内部删除三张表的对应行）。
3. **部分索引**：`ix_agent_runs_checkpoint_purge_candidates ON agent_runs(finished_at) WHERE finished_at IS NOT NULL AND checkpoint_purged_at IS NULL`。绝大多数 run 清理后就不在索引里，所以索引始终很小。查询条件必须“蕴含”索引条件才能用上它，测试用 `EXPLAIN`（关闭顺序扫描）验证。
4. **先删除、后记账**：记账失败只会导致下一轮重复删除，而重复删除无害；反过来先记账再删除，删除失败就会永远漏掉。单个线程删除失败不影响同一批的其他线程，下一轮重试。
5. **积压时连续处理**：一批（200 个）满了就立即处理下一批，不满才休息，避免长时间停机后积压的数据要很多个周期才清完。
6. **只处理已结束的 run**：条件 `finished_at IS NOT NULL`，排队中、执行中的 run 绝不会被清理。

## 后果

- 好处：checkpoint 的存储量与“最近 24 小时结束的 run + 进行中的 run”成正比，而不是随历史无限增长。
- 代价：结束超过 24 小时的 run 无法再查看图的中间状态（排查只能依赖日志与 `agent_runs`）。
- 注意：`DELETE` 不会立刻释放磁盘。PostgreSQL 把删除的行标记为死行，由 autovacuum 回收后供后续写入复用；要把空间还给操作系统需要 `VACUUM FULL`（会锁表）。实测：清理 16 个线程后三表占用仍是 384 kB，手动 `VACUUM` 后降到 216 kB。
- 已知局限：如果某个线程对应的 run 被删除了（目前没有删除 run 的功能），它的 checkpoint 不会被清理器发现；单进程运行，多实例时会重复删除（无害但浪费）。

## 验证

- 测试 4 个：只清理超过保留期的已结束 run（近期结束与执行中的保留）并且 checkpoint 真的被删除、第二轮无事可做；单个删除失败不影响其他且下一轮重试；积压超过一批时连续处理（检查间隔设为 1 小时也能清完）；候选查询能使用部分索引（`EXPLAIN`）。
- 变异检查 4 项均被抓住：去掉 `checkpoint_purged_at IS NULL`（同时让索引测试失败）、循环不连续处理、删除失败也记账、保留期比较方向写反。
- 容器实测：临时把保留期设为约 4 秒，开发库的 16 个 checkpoint 线程全部清除，19 个已结束 run 全部记账，没有误删。
