# 0024 - 阶段 6.1：前端设计系统与界面改版

**状态**：已决定（2026-10-24）。用户确认三项均按建议：简洁专业风格、跟随系统 + 手动切换的暗色模式、保留 Ant Design Vue 并用主题 token 统一。

**背景**：前端是按功能一块块加出来的（阶段 1 的聊天、阶段 2 的知识库、阶段 3 的图谱、阶段 4 的审批、阶段 5 的登录和看板），每次只求“能用”。阶段 6 要录演示视频、放 README 截图，界面就是项目给人的第一印象。这一步先审计现状，再定设计方向，最后统一改版。

## 一、现状审计（1440×900 与 800×600 两种窗口逐页截图）
| 问题 | 表现 | 影响 |
|---|---|---|
| 没有设计系统 | 7 个组件里散落 20 种硬编码颜色（`#888` 出现 10 次）；没有统一的字号、间距、圆角；全是组件库默认样式 | 页面之间不像一个产品；改一次配色要改十几处 |
| 全局导航放错地方 | “对话 / 知识库 / 用量 / 管理”是侧栏顶部的分段按钮；切换后侧栏内容整个变掉（对话列表消失） | 用户找不到“我在哪”；页面结构不稳定 |
| 聊天阅读体验 | 宽屏下消息横跨整个内容区（一行上百字）；没有角色标识；引用是很小的灰色标签；空对话只有一个图标 | 长回答难读；引用这个核心卖点看不出来 |
| 入口语义不清 | “新对话 / 深度调研”两个并列按钮；知识库选择器是顶部一条没有说明的下拉框 | 新用户不知道区别，也不知道知识库要先关联 |
| 状态反馈零散 | 等待、工具调用是一行灰字；审批卡片是突兀的黄色块；子任务进度是纯文本 | Agent 正在做什么——项目的亮点——看不出来 |
| 知识库页面拥挤 | 选择、新建、共享开关、上传挤在一行；检索测试在表格下方 | 操作没有主次 |
| 用量看板 | 指标没有卡片容器；稀疏数据画成尖峰折线；两张图上下堆叠 | 不像一个看板 |
| 登录页 | 空白背景上一个表单 | 第一屏没有任何产品信息 |
| 暗色、窄屏 | 都不支持；窗口变窄时侧栏挤压内容 | 演示环境不可控 |

## 二、改版要做的事（与风格选择无关）
1. **设计 token**：颜色（中性色阶 + 一个主色 + 成功 / 警告 / 危险 + 图表色板）、字号层级、间距、圆角、阴影，集中在一个文件里，同时喂给组件库主题和我们自己的样式（CSS 变量）。业务组件里不再出现硬编码颜色。
2. **应用外壳**：最左侧一条窄的全局导航（图标 + 文字提示：对话、知识库、用量、管理），右侧是页面自己的侧栏和内容。切换页面时结构不变。
3. **聊天**：居中的阅读列（最大宽度约 760px）；助手消息带标识、引用做成编号卡片（悬停看原文）；空对话显示欢迎区和示例问题；输入区固定在底部，带知识库关联入口与当前模式说明。
4. **Agent 状态可视化**：工具调用、检索、子任务做成时间线（进行中 / 完成 / 失败）；审批卡片与主题一致。
5. **知识库、用量、管理、登录**：按“标题区 + 操作区 + 内容卡片”统一页面结构；看板用指标卡片 + 柱状图（稀疏数据）+ 并排布局。
6. **响应式**：窄窗口下侧栏收起为抽屉。

## 三、待确认的选择
### 1. 视觉风格
| | A. 简洁专业（推荐） | B. 深色科技感 | C. 只修布局，保持组件库默认 |
|---|---|---|---|
| 样子 | 浅色为主、大量留白、低饱和中性色，一个品牌主色（靛蓝），细边框代替阴影 | 深色背景、霓虹强调色、渐变 | 现在的样子，加上新的布局 |
| 适合 | 企业知识库 / 客服场景；截图和视频清晰 | 演示有冲击力，但长时间阅读累、截图在 README 浅色背景上突兀 | 工作量最小 |

### 2. 暗色模式
| | A. 跟随系统 + 手动切换（推荐） | B. 只做浅色 |
|---|---|---|
| 代价 | token 里每个颜色定义两套；组件库用它的暗色算法 | 无 |
| 收益 | 设计 token 做好之后成本很低；面试时能讲“主题由 token 驱动” | — |

### 3. 组件库
| | A. 保留 Ant Design Vue，用主题 token + 自己的布局组件（推荐） | B. 换成 Naive UI | C. Tailwind + 自己写组件 |
|---|---|---|---|
| 代价 | 不重写业务逻辑；表格、表单、弹窗等复杂组件继续用 | 7 个组件全部重写，旧测试的交互要重新验证 | 工作量最大，复杂组件要自己实现 |
| 效果 | 组件库 4.x 的 token 体系可以把圆角、颜色、字号统一换掉；外壳和聊天区自己写 | 默认风格更现代 | 完全可控 |

## 四、验证方式（计划，结果见第六节）

- 浅色 / 暗色各一遍。
- 现有前端测试全部保留（只改样式和结构，状态机、接口层不动），构建体积记录前后对比。

## 五、实现（2026-10-24）
| 部件 | 代码 | 要点 |
|---|---|---|
| 设计 token | `web/src/theme/tokens.ts` | 浅色 / 深色两套调色板（锌灰中性色 + 靛蓝主色 + 状态色 + 图表色板）、字体、圆角；`antdTheme()` 喂给组件库（深色用它的暗色算法），`applyCssVars()` 写到 `:root` 的 `--an-*` 变量 |
| 主题模式 | `web/src/theme/useTheme.ts` | 跟随系统 / 浅色 / 深色；偏好存 localStorage（读写都 try/catch）；监听 `prefers-color-scheme`；provide / inject |
| 全局样式 | `web/src/styles/base.css` | 基础排版、细滚动条、Markdown 内容样式（`.an-md`）、页面结构类（`.an-page`、`.an-card`） |
| 外壳 | `App.vue`、`NavRail.vue` | 64px 全局导航栏（图标 + 文字，外观切换、账号菜单）；窄窗口（< 960px）对话列表收进抽屉 |
| 对话 | `ChatPanel.vue`、`ConversationList.vue` | 780px 阅读列；助手标识；引用编号卡片（悬停看原文）；产物文件卡片；工具调用时间线与子任务进度；空对话的说明和示例问题；输入区卡片；列表按今天 / 昨天 / 最近 7 天 / 更早分组、可搜索 |
| 状态机 | `pendingReply.ts` | 新增 `steps`：每次 `tool.started` 追加、`tool.finished` 按“同名、同子任务、进行中”的最后一个结束；接管时清空 |
| 其他页面 | `KnowledgePanel`、`UsagePanel`、`AdminPanel`、`LoginPanel`、`GraphPanel` | 知识库：左列表（我的 / 部门共享）+ 右详情（文档 / 检索测试 / 图谱）；看板：指标卡片 + 两张并排柱状图（随主题重画）；管理：部门与新建用户卡片 + 用户表（分页）；登录：品牌区 + 表单；图谱画布的颜色取自 token，切换主题时重设样式 |
| 部署 | `docker/nginx.conf` | `index.html` 不缓存、`/assets/` 长期缓存（文件名带内容哈希） |

## 六、验证
- 前端测试 60 个（新增对话分组、主题解析、工具时间线 9 个）；类型检查通过；业务组件里不再有硬编码颜色（只剩登录页和导航栏的品牌渐变）。
- 浏览器逐页检查（开发服务器 + Nginx 部署版）：1440×900 浅色 / 深色、390×844 手机宽度；对话（带引用的回答、空对话、深度调研的审批卡片、批准后的子任务与工具时间线、报告与下载卡片）、知识库、用量、管理、登录。调研一次真实调用约 $0.004。
- 构建体积：首屏 JS 由 645KB 变为约 660KB（gzip，+2%，新增图标和组件）；用量页（ECharts）仍是单独懒加载的包（174KB gzip）。
- 检查中发现并修复的问题见 dev-log（手机宽度横向滚动、密码框变形、标题不更新、等待计时包含审批时间、Nginx 缓存导致部署后仍是旧界面）。
