# 面试拷打准备

> 面试官深挖项目细节时用这份文档打底。每个小节尽量回答清楚："是什么 / 为什么这么做 / 踩过什么坑 / 如果重来会怎么改"。随开发推进持续补充——不要只写结论，要写清楚决策过程，这样才经得起追问。

## 项目一句话介绍

AgentNexus 是参考企业级知识智能体平台 [Yuxi](https://github.com/xerrors/Yuxi) 架构重构的「中台型」Agent 平台：核心能力（Agent 编排、RAG 知识库、知识图谱、MCP/Skills 扩展、沙盒工具执行、多租户权限）可复用，业务场景以插件形式接入，完整落地了"智能客服与工单自动化"场景，其余场景留接口占位。

## 为什么参考 Yuxi 而不是从零设计？

> 占位——建议补充你自己的真实理由，比如：想学习一个工程化程度高的多智能体平台如何处理排队、幂等、崩溃恢复这些生产级问题，而不是停留在网上大多数 demo 级 LangGraph 教程的水平。

## 为什么叫 AgentNexus？

Nexus（枢纽/连接点）对应项目的"中台"定位：核心能力是枢纽，业务场景包是接入枢纽的分支，命名直接体现架构思路而不是随意起的。

## 技术选型：哪里跟 Yuxi 一样，哪里不一样，为什么

完整对照表见 `docs/tech-tradeoffs.md`。核心话术："广度上对标 Yuxi，深度上按 solo 项目的体量做了基础设施取舍，每条取舍都留了决策记录（`docs/decisions/`），清楚如果要按生产级标准扩展应该怎么改——这是工程判断，不是偷懒。"
