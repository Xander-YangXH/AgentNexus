# 工具、沙盒与 MCP：让 Agent 动手，又不让它越界

> 配套《一条消息的完整旅程》《独立 worker 与租约》。阶段 4.2 让 Agent 能执行代码、读写文件、抓取网页，并通过 MCP 接入外部工具。
> 这一步的核心不是功能，而是安全边界：**模型能触发的执行，即使被提示注入完全控制，也碰不到宿主机、内部服务、密钥和别人的文件。**
> 决策记录：0021（含实验）。代码：`sandbox/`、`mcp_gateway/`、`agents/tools/`、`agents/skills.py`、`backend/skills/`。

## 0. 总图

```
                      ┌──────────── sandbox 网络（internal）────────────┐
worker ──HTTP + 令牌──▶ sandbox 服务（唯一持有 /var/run/docker.sock）
  │                      └─ 每次执行：新建加固容器（断网、只读、nobody、64 进程、256MB、0.5 核、超时 kill）
  │                         只挂载本对话的工作空间（卷 agentnexus_sandbox_workspaces 的子目录）
  │
  │                   ┌──────────── tools 网络（internal，不通外网）──────────────┐
  └──streamable HTTP──▶ mcp-gateway ──每次调用新起子进程──▶ mcp-server-fetch
                                                              │ --proxy-url
                                                              ▼
                                                        egress-proxy（Squid）──egress 网络──▶ 外网 80/443
                                                         按解析后的 IP 拒绝私有 / 回环 / 链路本地地址
```

## 1. 威胁模型：先说清楚防什么
- **攻击者能控制的**：发给 Agent 的文字，以及 Agent 读到的内容（知识库文档、网页、代码输出）。提示注入可以让模型调用它能用的任何工具，参数由攻击者决定。
- **要保护的**：宿主机；内部服务（Redis、Qdrant、Neo4j 在内网没有鉴权）；密钥；别的用户的文件。
- **原则**：边界由配置和服务端检查强制，不靠提示词。提示词里写“不要访问内网”只是让正常情况更顺，不算防线。

## 2. 沙盒：为什么要一个单独的服务
- **持有 Docker socket = 宿主机 root**：能创建特权容器、把宿主机根目录挂进来（实验里一行代码做到）。如果 worker 持有 socket，而 worker 里跑着受模型输出影响的逻辑，一个漏洞就是宿主机 root。
- **窄接口**：sandbox 服务只开放四个接口——执行代码、列文件、读文件、写文件。容器参数（断网、只读、用户、资源上限）写死在服务里，调用方改不了。
- **每次新建容器**：126ms。没有残留进程，上一次调用影响不到下一次。文件放在工作空间里，跨调用保留。
- **工作空间 = 对话**：同一对话的后续提问能用上一轮的文件；别的对话看不到。sandbox 服务自己在容器里运行，它看到的路径 Docker 不认识，所以按“命名卷 + 子目录”挂载（volume subpath，Docker SDK 7.2）。
- **路径校验**（`sandbox/files.py`）：拒绝空路径、绝对路径、NUL、`..` 越界，以及沙盒代码自己建的、指向外部的符号链接（先 `resolve()` 再检查是否仍在工作空间内）。

### 一个真实踩到的漏洞：URL 规范化
第一版客户端把模型给的路径放进 URL：`GET /workspaces/{ws}/files/{path}`。HTTP 客户端会规范化点段，
`../../<别的对话>/files/secret.txt` 发出去就成了 `/workspaces/<别的对话>/files/secret.txt`——服务端看到的是合法请求，校验没有机会执行。
修复：路径只放在查询参数 / 请求体里；工作空间 id 拼进 URL 前先校验是 UUID。

## 3. 联网工具：SSRF 和出口代理
- **SSRF**：fetch 的目标地址由模型决定。实验里它直接读到了 Qdrant 的集合列表。
- **只换网络不够**：放到独立网络后服务名解析不到了，但 `host.docker.internal:6333` 仍然可达。
- **出口代理**：工具所在网络设为 internal（本身不通外网），只能经 Squid 出去；Squid 按**解析后的 IP** 拒绝私有地址段。域名解析到内网、外网页面重定向到内网，都会在那一跳被拦下。
- **确认是“规则”拦下的**：fetch 访问内网地址时，报错是“robots.txt 返回 403”——它先取 robots.txt，第一跳就被拦了。核对 Squid 访问日志看到 `TCP_DENIED/403`，才算验证完成（实验时代理没在运行，结果也像“全部拦下”，教训在 0021）。

## 4. MCP 网关
- **为什么要网关**：第三方 MCP 服务是别人写的代码。实验发现官方 fetch 服务的依赖会在运行时执行 `npm install`（输出污染了协议流，还绕过了锁文件）。所以它们跑在一个只读、nobody、不装 Node、只接入 internal 网络的专用容器里。
- **每次调用新起子进程**：调用之间不共享状态；上游崩了不需要重连。代价是一次进程启动，compose 里抓 example.com 全程 0.7 秒。
- **子进程拿不到密钥**：mcp SDK 默认只传 HOME、PATH 等几个环境变量；网关配置里的 env 也被忽略（测试覆盖）。网关自己也没有任何密钥。
- **参数先校验**：按上游声明的 inputSchema 校验，不合法的调用到不了第三方代码。单次调用 60 秒超时。
- **worker 侧**（`agents/tools/mcp.py`）：直接用 mcp SDK 的客户端，每次新建会话（网关无状态）。网关不可用时没有联网工具，依赖它的技能不出现，60 秒后重试——worker 照常运行。

## 5. Skills：按需启用的工具
- 每个技能是 `backend/skills/<名称>.md`：YAML 文件头（名称、描述、工具列表）+ 正文（操作说明）。
- 系统提示只列名称和描述；模型调用 `load_skill(name)` 拿到正文，本次回答里才启用它列出的工具。
- **执行前再检查**：模型“猜”着调用、或被注入的内容诱导调用没启用的工具，直接拒绝（`工具不可用：…，先用 load_skill 加载`）。
- 技能的工具当前不可用（例如网关没起来）时，技能不出现在列表里。
- 加载技能后工具轮数上限从 3 提高到 8：数据分析要“写文件 → 执行 → 看报错 → 修改 → 再执行”。

## 6. 一次数据分析的完整过程（真实 DeepSeek）
用户贴了三行 CSV，让算总额、找最高月份、画折线图。事件流（前端据此显示“正在执行代码：…”）：
```
tool.started load_skill   data-analysis
tool.started list_files / write_file  data/sales_q1.csv
tool.started python_exec  import pandas as pd            ← 先探索数据
tool.started python_exec  import pandas as pd, matplotlib ← 计算 + 画图
tool.started python_exec  import pandas as pd, matplotlib ← 修正图的标签
→ 回答：总额 525，最高 2 月，图已保存为 chart.png
```
6 次模型调用，输入 8.2k token（缓存命中 6.3k），输出 1.0k，约 $0.002。

## 6.5 把文件交给用户：share_file（0027）
- 工具 `share_file(path)` 由 worker 执行：经 sandbox 服务原样读取文件（`/file/raw`，≤5MB），写成产物（与调研报告同一套：原件存储 + `artifacts` 表 + 下载接口），作为回复的附件。api 不需要沙盒令牌。
- 附件放在图的状态里（`ChatState.attachments`），随 checkpoint 保存：worker 被接管后不丢、不重复交付。一次回答最多 5 个。
- 只有安全的类型（图片、CSV、文本、PDF、xlsx 等）保留原类型；HTML、SVG 一律按二进制下载。前端只用 `<img>` 预览栅格图片。
- **踩过的坑**：compose 里工作空间是命名卷的子目录挂载，Docker 会把镜像里 `/workspace` 的 root 755 复制到**空**卷上（copy-up），新对话第一步执行代码就写不了文件；挂载加 `no_copy=True` 解决。本机测试用绑定挂载，测不出来。
- 修好后同一个问题：加载技能 → 执行代码（生成数据、画图、存 CSV）→ 交付两个文件 → 回答，4 次模型调用、8 秒。

## 8. 已知局限
- 网关暂时只接了 fetch，不支持需要密钥的 MCP 服务。
- sandbox 服务仍然持有 socket：它本身的漏洞仍是高风险点。它很小、不处理模型的自由文本（只接收代码字符串和路径），但更强的隔离（gVisor、Firecracker 等）留待以后评估。
